Get startedBắt đầu

1

Install acp and akCài acp và ak

ak installs AgentKit into a repo. acp decides what each repo should have and keeps every repo and worktree that way.

ak cài AgentKit vào một repo. acp quyết định mỗi repo cần có gì và giữ mọi repo, mọi worktree đúng như thế.

acp is one binary for macOS and Linux (arm64 and amd64). The repository is private, so you need the GitHub CLI signed in with access to thieung/acp. gh auth status should show your account.

acp là một binary cho macOS và Linux (arm64 và amd64). Repo đang private nên bạn cần GitHub CLI đã đăng nhập, có quyền vào thieung/acp. Lệnh gh auth status phải hiện đúng tài khoản của bạn.

gh release download v0.2.0-beta.1 -R thieung/acp -p install.sh -O - | sh
acp setup

You should seeKết quả mong đợi

ak       3.0.0-beta.36  (/Users/you/.local/bin/ak)
login    signed in (api_key)
doctor   healthy

The installer picks the build for your machine, checks its sha256, puts acp in ~/.local/bin and runs acp init. It only replaces an earlier acp; anything else in that place stops it. ACP_INSTALL_DIR picks another folder and ACP_NO_INIT=1 skips init.

Installer chọn bản dựng cho máy bạn, kiểm sha256, đặt acp vào ~/.local/bin rồi chạy acp init. Nó chỉ thay một bản acp cũ; gặp thứ gì khác ở chỗ đó thì dừng. ACP_INSTALL_DIR chọn thư mục khác, còn ACP_NO_INIT=1 bỏ bước init.

If ak is missing, let acp run AgentKit's official installer, then sign in. Without --apply, acp setup install-ak only shows what it would run.

Nếu chưa có ak, để acp chạy installer chính thức của AgentKit rồi đăng nhập. Không có --apply thì acp setup install-ak chỉ hiện những gì nó sẽ chạy.

acp setup install-ak --apply
acp setup login

To update acp later, run the installer again with a newer tag. Your control plane stays where it is.

Muốn cập nhật acp sau này, chạy lại installer với tag mới hơn. Control plane của bạn vẫn ở nguyên chỗ cũ.

2

Create a control planeTạo control plane

A small folder of JSON files that says what every project should have. The installer already created one in ~/agent-control-plane; put it in git so the decisions travel with you.

Một thư mục nhỏ gồm các file JSON, ghi rõ mỗi project cần có gì. Installer đã tạo sẵn một cái ở ~/agent-control-plane; hãy để nó trong git để các quyết định đi theo bạn sang máy khác.

acp init

You should seeKết quả mong đợi

  + projects/
  + skills/
  + runtime/
  + projects.local.json
  + agentkit-releases.lock.json
  + global-skills.json
  + .gitignore
  + AGENTS.md
control plane: /Users/you/agent-control-plane (recorded in /Users/you/.config/acp/root)
next:
  acp activity        repos you work in most
  acp add <path>      add one to the fleet
  acp scan            check that everything is linked

On a folder that already is a control plane, init adds only what is missing and keeps the rest. The recorded root lets every later command run from any folder; acp init --root DIR puts the plane somewhere else and records that instead. To keep it in git, run git init inside it and commit; machine paths and backups are already in its .gitignore. What each file holds is under Files.

Với thư mục đã là control plane, init chỉ thêm những gì còn thiếu và giữ nguyên phần còn lại. Nhờ root đã ghi, mọi lệnh sau đó chạy được từ bất kỳ thư mục nào; acp init --root DIR đặt control plane ở chỗ khác và ghi lại chỗ đó. Muốn đưa nó vào git, chạy git init bên trong rồi commit; đường dẫn máy và bản sao lưu đã nằm sẵn trong .gitignore. Mỗi file chứa gì có ở mục File.

3

Add a projectThêm một project

Point acp at the main checkout of a repo. It writes the manifest, records where the repo lives on this machine, and syncs it.

Chỉ cho acp thư mục checkout chính của một repo. Nó ghi manifest, lưu vị trí repo trên máy này và sync repo đó.

Replace ~/code/my-app with your own repo. Look first, then add:

Thay ~/code/my-app bằng repo của bạn. Xem trước, rồi mới thêm:

acp add ~/code/my-app --dry-run
acp add ~/code/my-app

You should see, after AgentKit's own install outputKết quả mong đợi, sau phần output cài đặt của AgentKit

added my-app -> /Users/you/code/my-app  (edit projects/my-app.json for personal skills)
my-app  /Users/you/code/my-app  in sync

A new project gets AgentKit's engineer kit on the beta channel, for Claude Code and Codex. Pass --no-agentkit for personal skills only, or choose with --kit, --channel and --targets. The manifest it writes:

Project mới nhận kit engineer của AgentKit ở kênh beta, cho Claude Code và Codex. Dùng --no-agentkit nếu chỉ cần skill cá nhân, hoặc tự chọn bằng --kit, --channel, --targets. Manifest nó ghi ra:

{
  "id": "my-app",
  "agentkit": { "kit": "engineer", "channel": "beta", "targets": ["claude-code", "codex"], "skills": "all" },
  "skills": []
}

Starting from scratch? acp new ~/code/my-app creates the folder (or runs git init in an existing one, or takes an existing repo), adds it and installs AgentKit for Claude Code only. Pick runtimes with --runtimes claude,codex and personal skills with --skills; defaults can live in project-defaults.json. No commit is made, and what acp and AgentKit created is listed in .git/info/exclude so a first git add -A leaves it out.

Bắt đầu từ con số không? acp new ~/code/my-app tạo thư mục (hoặc chạy git init trong thư mục có sẵn, hoặc nhận repo có sẵn), thêm vào fleet và cài AgentKit chỉ cho Claude Code. Chọn runtime bằng --runtimes claude,codex và skill cá nhân bằng --skills; giá trị mặc định có thể đặt trong project-defaults.json. acp không commit, và những gì acp cùng AgentKit tạo ra được ghi vào .git/info/exclude để lần git add -A đầu tiên bỏ qua chúng.

4

Check and sync itKiểm tra và sync

Run acp on its own to see every project. A check mark means the repo matches its manifest.

Gõ acp không kèm gì để xem mọi project. Dấu tích nghĩa là repo khớp với manifest của nó.

acp

You should seeKết quả mong đợi

PROJECT  AGENTKIT                              PERSONAL  WORKTREES
my-app   cc 3.0.0-beta.36 codex 3.0.0-beta.36  0/0       -          ✓
pinned: beta/engineer 3.0.0-beta.36

When a project drifts, because you edited its manifest or AgentKit moved, sync it from inside the repo. The dry run lists each change first.

Khi một project bị lệch, do bạn sửa manifest hoặc AgentKit có bản mới, hãy sync nó từ trong repo. Bản dry run liệt kê từng thay đổi trước.

cd ~/code/my-app
acp sync --dry-run
acp sync

You should seeKết quả mong đợi

my-app  /Users/you/code/my-app  in sync

A sync installs or refreshes AgentKit at the pinned version, links your personal skills, and links every worktree to the main checkout's agent files. If something is off, see When something is off.

Một lần sync cài hoặc làm mới AgentKit theo bản đã ghim, link skill cá nhân, và link mọi worktree tới file agent của checkout chính. Nếu có gì đó lệch, xem Khi có gì đó lệch.

5

See it in the browserXem trên trình duyệt

A dashboard of the same projects, on your machine only. Each button runs one allowed acp command, and only from the preview you just read.

Một bảng điều khiển cho cùng các project đó, chỉ chạy trên máy bạn. Mỗi nút chạy đúng một lệnh acp được cho phép, và chỉ từ bản xem trước bạn vừa đọc.

acp web

You should see, and your browser opens the page signed inKết quả mong đợi, trình duyệt tự mở trang đã đăng nhập

acp web: http://127.0.0.1:8780 (Ctrl-C to stop)
  • Four parts: Overview with a Scan button, Projects & Skills, AgentKit & Runtimes, and Hooks, MCP & Settings.
  • Every change opens a preview of what it will change and what it leaves alone. Apply is enabled only from that preview, and acp checks it again right before applying.
  • "Gom bản sao cũ" replaces old copied folders in worktrees with links, after backing them up; see Worktrees with old copies.
  • The sign-in code in the URL works once. If you lose the tab, stop acp web and start it again.
  • The dashboard and the scan are in Vietnamese for now.
  • Bốn mục: Tổng quan có nút Quét, Dự án & Skill, AgentKit & Runtime, và Hook, MCP & Cài đặt.
  • Mọi thay đổi mở bản xem trước: sẽ đổi gì và không đụng tới gì. Nút Áp dụng chỉ bật từ bản xem trước đó, và acp kiểm tra lại ngay trước khi áp dụng.
  • "Gom bản sao cũ" thay các thư mục copy cũ trong worktree bằng link, sau khi đã sao lưu; xem Worktree có bản copy cũ.
  • Mã đăng nhập trong URL chỉ dùng được một lần. Lỡ đóng tab thì dừng acp web rồi chạy lại.

Going furtherDùng nhiều hơn

Change a project's skillsĐổi skill của một project

Rather than editing JSON by hand, ask acp. It prints the manifest diff and what the sync would do, and changes nothing until you add --apply.

Thay vì sửa JSON bằng tay, hãy để acp làm. Nó in diff của manifest và những gì sync sẽ làm, và không đổi gì cho đến khi bạn thêm --apply.

acp skills list my-app
acp skills set my-app --add release-notes --remove ak-shopify
acp skills set my-app --add release-notes --remove ak-shopify --apply

Personal skills live in the control plane's skills/ folder, one folder per skill. acp kit add my-app gives AgentKit to a project that was added without it.

Skill cá nhân nằm trong thư mục skills/ của control plane, mỗi skill một thư mục. acp kit add my-app thêm AgentKit cho project lúc thêm vào chưa có.

Many projects and worktreesNhiều project và worktree

Once several repos are in, work on all of them at once. Check the plan before a sync that touches everything.

Khi đã có nhiều repo, bạn có thể xử lý tất cả cùng lúc. Hãy xem kế hoạch trước khi chạy một lần sync chạm tới mọi thứ.

acp sync --all --dry-run

Then run acp sync --all. In CI, acp doctor exits with 1 when any project drifted.

Sau đó chạy acp sync --all. Trong CI, acp doctor trả mã 1 khi có project bị lệch.

New worktreesWorktree mới

Worktrees appear all the time. Install the session hook once, and Claude Code and Codex link each new worktree when a session starts in it.

Worktree mới sinh ra liên tục. Cài session hook một lần, Claude Code và Codex sẽ tự link worktree mới khi một phiên bắt đầu trong đó.

acp hooks install --dry-run
acp hooks install

Worktrees with old copiesWorktree có bản copy cũ

A worktree created before acp may hold a real .claude folder copied from main, which hides newer skills. A sync leaves it alone and reports it. --adopt moves each such folder into runtime/backups and puts a link in its place.

Worktree tạo trước khi có acp có thể chứa thư mục .claude thật được copy từ main, che mất các skill mới hơn. Sync thường để nguyên và báo lại. --adopt chuyển từng thư mục đó vào runtime/backups rồi đặt link vào chỗ cũ.

acp sync my-app --adopt --dry-run
acp sync my-app --adopt

A new AgentKit releaseBản AgentKit mới

acp upgrade updates ak, pins the channel's latest kit in the lock file and syncs every project. acp upgrade --dry-run shows the versions first.

acp upgrade cập nhật ak, ghim kit mới nhất của kênh vào file lock và sync mọi project. acp upgrade --dry-run cho xem phiên bản trước.

Connect an agentKết nối agent

Ask your agent "which projects need a sync?" and it answers from acp_scan and acp_status. Ask it to fix something and it shows you the preview and the exact command; you run it, or press Apply in acp web.

Hỏi agent "project nào cần sync?" và nó trả lời từ acp_scan và acp_status. Nhờ nó sửa thì nó cho bạn xem bản xem trước và đúng lệnh cần chạy; bạn tự chạy lệnh đó, hoặc bấm Áp dụng trong acp web.

Connect once per machine. --scope user makes acp available in every Claude Code project.

Mỗi máy chỉ cần kết nối một lần. --scope user giúp acp có mặt trong mọi project của Claude Code.

claude mcp add --scope user acp -- ~/.local/bin/acp mcp
codex mcp add acp -- ~/.local/bin/acp mcp

To confirm, run claude mcp list or codex mcp list. acp should be listed; Claude Code also shows it as connected.

Để kiểm tra, chạy claude mcp list hoặc codex mcp list. acp phải có trong danh sách; Claude Code còn hiện nó là đã kết nối.

The server works on the control plane acp init recorded. To point it elsewhere, pass ACP_ROOT: -e ACP_ROOT=/path for Claude Code, --env ACP_ROOT=/path for Codex. Any other MCP client can launch acp mcp over stdio.

Server làm việc trên control plane mà acp init đã ghi. Muốn trỏ chỗ khác, truyền ACP_ROOT: -e ACP_ROOT=/path với Claude Code, --env ACP_ROOT=/path với Codex. Client MCP khác cũng chạy được acp mcp qua stdio.

Agents read, you apply. All four tools only read or preview. No tool changes a file, so a busy agent cannot sync, relink or rewrite settings on its own. The list is under MCP tools.

Agent đọc, bạn áp dụng. Cả bốn tool chỉ đọc hoặc xem trước. Không tool nào đổi file, nên agent không tự sync, link lại hay sửa cài đặt được. Danh sách ở mục Tool MCP.

When something is offKhi có gì đó lệch

acp never repairs on its own. When a sync fails it stops and says why; acp scan then tells you, in plain words, what is off and how to fix it.

acp không bao giờ tự sửa. Khi sync lỗi, nó dừng và nói lý do; sau đó acp scan cho bạn biết bằng lời thường chỗ nào lệch và sửa thế nào.

acp scan

For exampleVí dụ

Hook, MCP & Cài đặt  1 mục
  [cần sửa] Chưa cài hook tự gắn skill cho worktree  acp_hook_missing
    Xem trước bằng lệnh bên dưới, rồi chạy acp hooks install (có bản sao lưu).
    xem trước: acp hooks install --dry-run
chi tiết một mục: acp explain <code>

Scan only reads. It checks each project, each worktree and the shared pieces (hooks, MCP servers, global skills, ak), with a time limit for each. Every finding has a stable code and a level: error, warn, decide or info. When acp can fix it, the finding carries the command to preview first. acp scan --module projects narrows it to one part.

Scan chỉ đọc. Nó kiểm tra từng project, từng worktree và các phần dùng chung (hook, MCP server, skill dùng chung, ak), mỗi phần có giới hạn thời gian. Mỗi kết quả có mã cố định và mức độ: error, warn, decide hoặc info. Khi acp sửa được, kết quả kèm lệnh để xem trước. acp scan --module projects chỉ quét một phần.

acp explain CODE gives the four parts of a finding: what happened, why it matters, what happens if you leave it, and what to do, with the terms it uses.

acp explain CODE cho đủ bốn phần của một kết quả: chuyện gì, vì sao quan trọng, nếu bỏ qua thì sao, và nên làm gì, kèm giải thích thuật ngữ.

acp may changeacp được phép đổi

  • Links it made, which it records in each checkout's ledger
  • AgentKit's own files, through ak
  • Settings files, after a backup in runtime/backups
  • Các link do nó tạo, đã ghi trong ledger của mỗi checkout
  • File riêng của AgentKit, qua ak
  • File cài đặt, sau khi sao lưu vào runtime/backups

acp neveracp không bao giờ

  • Removes or replaces a path git tracks
  • Replaces a real folder or a link it did not make
  • Starts a second agent to repair things
  • Gỡ hay thay một path git đang theo dõi
  • Thay một thư mục thật hay một link không do nó tạo
  • Mở thêm agent để tự sửa

Undo acp in a checkoutGỡ những gì acp làm trong một checkout

acp unlink PATH removes the links acp made in that checkout, its exclude file and its ledger. acp remove ID takes a whole project out of the fleet; without --yes it only shows what it would do.

acp unlink PATH gỡ các link acp đã tạo trong checkout đó, cùng file exclude và ledger của nó. acp remove ID đưa cả project ra khỏi fleet; không có --yes thì nó chỉ hiện những gì sẽ làm.

acp unlink ~/code/my-app-feature --dry-run
acp remove my-app

acp finds the control plane from $ACP_ROOT, then the git checkout you are in when it is a control plane with projects.local.json, then the root acp init recorded, then ~/agent-control-plane.

acp tìm control plane theo thứ tự: $ACP_ROOT, rồi checkout git bạn đang đứng nếu nó là control plane có projects.local.json, rồi root mà acp init đã ghi, rồi ~/agent-control-plane.
